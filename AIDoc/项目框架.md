## 1. 定位

Cocos 打龙游戏的 Node 后端。业务几乎全部走 **一个** `POST /gateway`：数字 `cmd` + LZString 压缩信封 + MD5 签名。没有按资源拆开的 REST API。

| 项 | 现状 |
|---|---|
| 运行时 | Node.js + TypeScript（`strict`，CommonJS，产物 `dist/`） |
| HTTP | Express 4 |
| 库 | MongoDB + Mongoose 8 |
| 登录凭证 | JWT，两种：`account` / `game`；密码 bcrypt |
| 开发启动 | `npm run dev` → `scripts/dev.mjs`（本地 mongod + `tsx watch`） |
| 包管理 | npm |

另有两个非网关入口，只给开发和旧登录场景用，见第 3 节。

## 2. 分层

调用链：

```
index.ts
  → protocol/dispatch.ts          解信封、验 token、查表、统一回包
    → protocol/handlers/*.ts      取参、守卫、转发
      → services/*.ts             规则、校验、数值
        → repositories/*.ts       Mongo CRUD，Document → Record
          → models/*.ts           Schema + 索引
```

| 目录 | 职责 | 改代码时 |
|---|---|---|
| `src/index.ts` | Express、连库、挂路由 | 不在这里加业务 |
| `src/protocol/cmd.ts` | 协议号常量 `CMD`、`actionOf` | 新协议先加这里，禁止魔法数字 |
| `src/protocol/dispatch.ts` | 网关唯一处理函数 | 新 cmd **不用改它** |
| `src/protocol/handlers/` | 按域拆的薄 handler，`index.ts` 展开合并 | 只取参 + `requireAuth` / `requireAccount` + 调 service |
| `src/services/` | 业务核心 | 不直接 `import` Model |
| `src/repositories/` | 查询与写入 | 不写游戏规则 |
| `src/models/` | Schema、索引、启动迁移 | 不写业务方法 |
| `src/types/` | Record、DTO、`toXxxRecord` | handler / service 只碰 Record |
| `src/config/*.json` | 静态表，启动时由 `config.service.ts` 进内存 | 运行期只读；改表要重启 |
| `src/integrations/` | 微信 code 换 openid、Google idToken 验签 | 密钥只在 `.env`；`AUTH_STUB=1` 走桩 |
| `src/constants/loginType.ts` | `LoginType` 枚举 | 注释里的「cmd=2」已过时，登录号是 `10001` |
| `src/utils/` | 连库、信封、错误类、请求上下文 | |
| `src/middleware/auth.ts` | Bearer JWT 中间件 | **入口没有挂它**。网关鉴权在 `dispatch.ts` 里完成 |

handler 汇总在 `handlers/index.ts`：`system + auth + user + weapon + zone`。

## 3. 进程入口

`src/index.ts` 启动顺序：`connectDB()` → `listen(PORT || 3000)`。

`connectDB`（`utils/db.ts`）：

1. `ENABLE_MEMORY_DB=true` 时用 `mongodb-memory-server`，否则 `MONGO_URI`（默认 `mongodb://localhost:27017/gameServer`）。
2. `migrateUsersToAccounts()`：把旧 User 文档里的账号字段拆到 Account。
3. `syncAccountIndexes()` / `syncUserIndexes()`。

路由：

| 方法 / 路径 | 作用 |
|---|---|
| `GET /health` | `{ code: 0, msg: 'ok' }`，给启动器和 e2e 探活 |
| `GET /sdk/sdkDev.php?action=autoLogin&openId=` | 兼容前端 LoginScene 的 PHP 自动登录。明文 JSON，**不是**网关信封。内部 `authService.autoLogin`，返回 account token 和 `server_info.host`（默认本机 `/gateway`，可用 `GATEWAY_PUBLIC_URL` 覆盖） |
| `POST /gateway` | 全部游戏协议 |

`index.ts` 底部还有一个 Express 错误中间件：`BusinessError` 且 `code===401` 时 HTTP 401，其它业务错 HTTP 200，未知错误 HTTP 500。它只管**没被网关自己 catch 的异常**。网关内部永远 `res.status(200)`。

## 4. 网关协议

实现：`utils/crypto.ts` 的 `decodeRequest`，`utils/gateway.ts` 的 `buildResponse`，`protocol/dispatch.ts` 串联。

### 请求

`Content-Type: application/json`

```json
{ "action": 10001, "data": "<LZString.compressToBase64>", "sign": "<md5 hex>", "retry": false }
```

内层明文：

```json
{ "puid": "", "token": "", "server_id": 1, "g_id": 0, "...业务字段": "..." }
```

- 验签：`md5(data + GATEWAY_SIGN_KEY) === sign`。请求侧**不允许** `sign === 密钥` 绕过。
- 密钥：环境变量 `GATEWAY_SIGN_KEY`，默认与前端 `GlobalDefine` / `getRequestSecret()` 相同，常量在 `utils/gateway.ts`。
- 解压后剥离信封字段：`puid`（兼容旧名 `uid`；`0` / `""` / `null` 当没传）、`token`、`server_id`、`g_id`（后端暂不使用）。其余进 `payload`。
- `puid`、`server_id` 放进 handler 的 `ctx`，不进 payload。

### 响应

永远 HTTP 200，对象 `{ code, action, data, error, sign }`。

| 情况 | code | error | data | sign |
|---|---|---|---|---|
| 成功 | `0` | `0` | 业务对象的 LZ 压缩串 | `md5(data + KEY)` |
| 业务失败 | **负数**（`BusinessError.code` 取负） | `0` | 压缩后的 `{ message }` | `md5(data + KEY)` |
| 系统失败 | `0`（`buildResponse` 在 `error!==0` 时强制写成 0） | 下表语义码 | `""` | **密钥原文** |

系统码在 `utils/errors.ts` 的 `SYS_ERROR`，由 `dispatch.classifyError` 把旧内部码映射过去：

| 内部 `BusinessError.code` | 响应 `error` | 含义 |
|---|---|---|
| `401` | `-10015` | 未登录 / token 无效（前端可据此踢下线） |
| `4004` | `-10004` | 未知协议，或缺 action/data/sign |
| `4001` | `-1000004` | 签名失败 |
| `400` / `4000` | `-1000001` | 参数或请求体非法 |
| `500` 及非 BusinessError | `1` | 内部错误 |
| 其它正数 | `code = -abs(raw)`，`error = 0` | 普通业务失败 |

handler 不要自己 try/catch。抛 `new BusinessError(message, code)` 即可。

### 鉴权（在 dispatch 内，不走 middleware）

有 `token` 就 `authService.verifyToken`。失败则清空身份，等守卫决定要不要 401。

`protocol/handlers/types.ts`：

- `requireAuth(ctx)`：必须 `kind==='game'` 且有 `userId`。游戏内协议用这个。
- `requireAccount(ctx)`：只要有 `accountId`。选区用这个，account token 和 game token 都能过。

## 6. 账号、角色、登录

两层数据，各区隔离：

- **Account**（`models/account.model.ts`）：跨区账号。`username` 唯一；`passwordHash`；`thirdParties[{provider, openid}]` 联合唯一（sparse）。
- **User**（`models/user.model.ts`）：区角色。`accountId + zoneId` 唯一（sparse）；`username + zoneId` 唯一。字段：`coins`、`userData`（Mixed）、`weapons`（Mixed）、`zoneId`。`passwordHash` / `thirdParties` 只给迁移读，新角色不写。

新角色初始金币 `STARTER_COINS = 1000`（`types/player.ts`），`userData = { level: 1, exp: 0 }`，默认区 `DEFAULT_ZONE_ID = 1`。并发创建撞唯一索引 `11000` 时，repo 再查一次已有文档，当成幂等成功。

### Token

密钥 `JWT_SECRET`（默认 `change_this_secret`），过期 `JWT_EXPIRES_IN`（默认 `7d`）。

| kind | 载荷 | 能做什么 |
|---|---|---|
| `account` | `accountId`, `username` | 区列表、进区；也能再打 10001 |
| `game` | `accountId`, `userId`, `username`, `zoneId` | 角色、背包、武器、存档 |

无 `kind` 但有 `userId` 的旧 token，按 game 处理。

### cmd 10001 分支（`handlers/auth.ts`）

按顺序，命中即停：

1. `ctx` 里已有 `accountId`（请求带了合法 token）→ 复用该账号，重签 account token。
2. `loginType===0` 且带用户名密码 → `authService.login`。库里没有就**直接建号**（登录即注册）。密码至少 6 位，错误密码拒绝。
3. 信封有 `puid` → `authService.autoLogin(puid)`，用户名就是 openId。
4. `loginType!==0` → 第三方：`1` 微信（body.`code`）、`2` Google（body.`idToken`）。`10` 木风、`11` 电魂只在枚举里，**没有实现**。
5. 否则 4000。

然后**总会**按 `ctx.serverId`（缺省再看 payload，再缺省 1 区）`userRepo.createInZone`，并签发 `gameToken`。因此走 10001 的客户端可以不再调 cmd 14。cmd 13/14 仍然可用。

`register()` 在 service 里还在，没有对应 cmd。

第三方：`AUTH_STUB=1` 不联网，openid/sub 由入参派生。否则微信要 `WECHAT_APPID` / `WECHAT_SECRET`，Google 要 `GOOGLE_CLIENT_ID`（RS256，证书缓存 1 小时）。

## 7. 业务不变式

**金币只能服务端改。** `userService.saveUserData`（cmd 15 和 1001）会 `delete data.coins`。`level` / `exp` 必须是有限且 ≥ 0 的数。入参可以是裸对象，或仅含一层 `{ userData }`。

**扣费用条件更新。** `userRepo.updateAtomic(id, update, { coins: { $gte: cost } })`。返回 null 就当资源不足或并发冲突。武器解锁、升级走这条。

**武器（`weapon.service.ts` + `config/weapons.json`）：**

- 解锁：配置存在、尚未解锁、金币够 → `weapons[id] = { level: 1, unlocked: true }`，扣 `unlockCost.coins`。
- 升级：必须已解锁，且 `targetLevel === 当前 + 1`，不超过 `maxLevel`，费用取 `upgradeCost[目标等级].coins`。
- 穿戴 / 卸下：只改 `isFitOut`，不扣费。请求字段是 `id`（解锁/升级用的是 `weaponId`）。

cmd 15 仍会整包覆盖 `userData`，**不会**改 `weapons` 集合字段。若前端把武器状态只放在 `userData` 里经 cmd 15 回写，和 cmd 8/9/16/17 写的 `weapons` 字段是两条存储，改相关逻辑时要先确认前端落在哪边。

**配置不下发是旧约定，BAG 是例外：** `weaponService.getWeapons` 把 `configService.getAllWeapons()` 放进了 10010 的回包。items / levels / zones 没有对应下发接口。

区服：`zones.json` 现有 1 区、2 区，`status` 为 `open | maintenance | closed`。`zoneService.enter` 只允许 `open`。

## 9. 加一个业务的顺序

1. `src/protocol/cmd.ts` 加常量（数字与前端 `MSD_ID` 同时定）。
2. 需要表就加 `src/config/*.json` 和 `config.service.ts`。
3. 需要新集合就加 `models` → `types` 里 `toXxxRecord` → `repositories`。
4. `services` 写规则。扣费必须走 `updateAtomic` 条件。
5. 在对应 `handlers/*.ts` 加一条：守卫 + 调 service。新文件要在 `handlers/index.ts` 展开进去。
6. **不用改 `dispatch.ts`。**

守卫选择：游戏数据用 `requireAuth`；只认账号、还不需要区角色用 `requireAccount`；登录本身不加守卫。

## 10. 类型落点（避免改错文件）

同一概念目前有两份声明，**运行路径用的是左边**：

| 概念 | 实际被网关使用 | 另一份（尚未成为主路径） |
|---|---|---|
| `Ctx` / `Handler` | `protocol/handlers/types.ts` | `types/protocol.ts`（多一个 `clientIp`） |
| `DecodedRequest` | `utils/crypto.ts` | `types/gateway.ts` |
| `GatewayResponse` / `buildResponse` | `utils/gateway.ts` | `types/gateway.ts` 只有接口 |
| `TokenPayload` 等 | `services/auth.service.ts` 自己导出 | `types/auth.ts` |
| `ZoneListItem` | `services/zone.service.ts` 自己导出 | `types/zone.ts` |

`types/index.ts` 会把上述 `types/*` 全部再导出。改字段时两处一起改，或先收成一处再改。

`_id` 在 `toPlayerRecord` / `toAccountRecord` 里转成字符串 `id`。service 不要把 Mongoose Document 传出 repo。

## 12. 改代码时不要破坏的点

1. 游戏协议只加在 `/gateway`，用 `CMD` 常量。
2. handler 保持薄；规则放 service；数据库放 repository。
3. 网关错误走 `BusinessError`，HTTP 保持 200。系统错误码走 `SYS_ERROR`，不要在 handler 里手写 `-10015` 这类响应。
4. 客户端存档不能写入 `coins`。扣金币用带 `coins: { $gte: cost }` 的原子更新。
5. 第三方登录以服务端换到的 openid / 验过的 `sub` 为准。
6. 配置 JSON 当只读数据，不把玩家进度写进配置表。
