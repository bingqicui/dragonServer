# 打龙服务器 - 执行文档（AI 开发手册）

> 本文件是 AI 在本项目中执行任务时**必须遵循**的实操手册，提炼自 `AI_RULES.md` + 实际代码。
> 每次动手改代码前先扫一遍「禁止事项」与「分层调用链」。

---

## 1. 项目定位与技术栈

- **定位**：Cocos Creator 游戏后端。唯一入口 `POST /gateway`，**不提供任何 REST 业务接口**。
- 技术栈：Node.js + TypeScript + Express 4 + MongoDB(Mongoose) + JWT(双 token) + bcryptjs。
- 包管理 npm；版本控制 SVN（非 Git）；开发用 `tsx watch`。

---

## 2. 分层架构与调用链（铁律）

```
dispatch.ts → handlers/xxx.ts → services/xxx.service.ts → repositories/xxx.repo.ts → models/xxx.model.ts
```

| 层 | 职责 | 红线 |
|---|---|---|
| `protocol/dispatch.ts` | 解密 → 验 token 建 ctx → 按 cmd 查 handler → 统一响应（永远 HTTP 200） | 不写业务；新增 cmd **无需改它** |
| `protocol/handlers/*` | 极薄：取参数 + 调守卫（`requireAuth`/`requireAccount`） + 转发 service | **不写业务逻辑** |
| `services/*` | **所有业务规则、校验、数值计算**都在这里（核心层） | 不直接碰 Mongoose Model，只调 repo |
| `repositories/*` | CRUD 封装，Mongoose Document → `toXxxRecord` 纯对象 | 不写业务规则 |
| `models/*` | 仅 Schema + 索引定义 | 无业务方法 |
| `types/*` | 纯 TS 类型 + `toXxxRecord(doc)` 转换（`_id`→`id`） | — |
| `utils/*` | `db.ts`(连接) / `crypto.ts`(信封解密) / `errors.ts`(`BusinessError`) | — |
| `config/*.json` | 静态配置表，启动由 `config.service.ts` 全量载入内存、**运行期只读** | 不存动态数据；**不下发给前端** |
| `integrations/*` | 第三方 SDK（微信/Google），`AUTH_STUB=1` 走桩 | 密钥只存服务端 `.env` |

`handlers/index.ts` 用 `{...system, ...auth, ...user, ...weapon, ...zone}` 汇总，dispatch 自动查表。

## 3. 协议规则（/gateway）

- **请求**（`application/x-www-form-urlencoded`，body 为裸 JSON / 加密串，`dispatch` 用 `express.text` 读取再手动解析）：
  - 明文：`{ cmd, payload, token?, resVer?, isDevVersion? }`
  - 加密：`{ o: base64(UTF8(内层JSON)), s: MD5(内层JSON + REQUEST_SECRET) }`（`REQUEST_SECRET` 默认 `'9572'`，生产写 `.env`）
- **响应**：**永远 HTTP 200**，错误只进 `ErrorCode` + `Msg`，否则前端会当网络故障反复重试。
  - 成功：`{ ErrorCode: 0, Payload: {...}, t }`
  - 失败：`{ ErrorCode: <码>, Payload: null, Msg: <信息>, t }`（catch 兜底 500）
- **cmd 数字**全部在 `src/protocol/cmd.ts` 的 `CMD` 常量定义（前端 `MSD_ID` 对齐），**禁止硬编码数字**。

| cmd | 含义 | 守卫 |
|---|---|---|
| 2 | 登录/取 token（loginType 0 账号密码 /1 微信 /2 Google） | 无 |
| 5 | 心跳 | 无 |
| 13 | 区列表 | `requireAccount` |
| 14 | 进区（拿 game token） | `requireAccount` |
| 4 | 角色信息（含 serverTime） | `requireAuth` |
| 6 | 红点 | `requireAuth` |
| 7 | 背包/武器 | `requireAuth` |
| 8 | 武器解锁 | `requireAuth` |
| 9 | 武器升级 | `requireAuth` |
| 1001 | 引导进度存档 | `requireAuth` |

## 4. 账号 / 角色 / Token 体系

- **双层**：`Account`（跨区共享，存登录凭证：用户名密码 hash / 第三方 openid）↔ `User/Player`（每区一份独立角色，存 coins、weapons、userData、zoneId）。一个账号可在多区各建独立角色，数据完全隔离。
- **双 token**（JWT，secret=`JWT_SECRET`，exp=`JWT_EXPIRES_IN`）：
  - `account` token：`{kind:'account', accountId, username}` —— 登录后未选区用，只能看区列表/进区
  - `game` token：`{kind:'game', accountId, userId, username, zoneId}` —— 选区后用，可操作用户数据
- 登录流程：cmd=2 拿 account token + 区列表 → cmd=13 区列表 → cmd=14 进区拿 game token → 后续游戏业务全用 game token。
- `dispatch.ts` 若有 token 会先 `verifyToken` 建 `ctx`；旧 token（有 userId 无 kind）按 game 处理。无效 token 清空 ctx，由守卫按需抛 401。

## 5. 服务器权威原则（关键不变式）

1. **货币 `coins` 只能服务端增减**：存档(cmd=1001) 里 `userService.saveUserData` 强制 `delete data.coins`；已知数值字段（level/exp）做非负校验。
2. **扣费用原子条件更新**：`userRepo.updateAtomic(id, update, { coins: { $gte: cost } })`，并发下不会扣成负数；返回 null 即资源不足/冲突，抛业务错误。
3. **武器系统**：解锁扣费写 `weapons[id]={level:1,unlocked:true}`；升级**只能逐级**（`targetLevel=当前+1`、不超 `maxLevel`），费用查配置表，不足拒绝。
4. 第三方登录**服务端验签**：微信拿 code 换 openid（密钥不下行）；Google 验 idToken 签名（RS256，证书缓存 1h）。`AUTH_STUB=1` 时不联网返回确定性桩。

## 6. 新增业务模块 Checklist（如「副本」）

1. `src/protocol/cmd.ts`：加协议号常量（数字由服务器定义）
2. `src/config/`：有配置则加 JSON
3. `src/services/config.service.ts`：加 interface + cache + getter（若用到配置）
4. `src/types/`：加 DTO 类型 + `toXxxRecord`
5. `src/models/`：新集合加 Schema + 索引
6. `src/repositories/`：加数据访问层
7. `src/services/`：加业务逻辑（核心，规则/校验/数值都在这里）
8. `src/protocol/handlers/xxx.ts`：加 handler 条目（参数提取 + 守卫 + 转发 service），并 import 到 `handlers/index.ts` 汇总
9. `e2e_test.js`：加对应测试用例

> **dispatch.ts / handlers/index.ts 通常无需改**（自动汇总）。前端需同步改 `MSD_ID`。

## 7. 错误码约定

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 401 | 未登录 / token 无效 |
| 400 | 参数错误 |
| 4000 | 请求体格式错误 |
| 4001 | 签名校验失败 |
| 4004 | 未知 cmd |
| 500 | 服务器内部错误 |

业务错误统一 `throw new BusinessError('信息', code)`；handler 层**不写 try-catch**，由 dispatch 统一捕获转响应。

## 8. 启动 / 调试 / 测试

```bash
npm install
npm run dev            # 一键起 本地MongoDB(../serverApps/mongodb/data) + tsx watch 服务器
                       # 环境变量: MONGO_TAKEOVER=0 / SERVER_TAKEOVER=0 / DEV_DRY_RUN=1
npm run typecheck      # tsc --noEmit
npm run build          # tsc 编译到 dist/
node e2e_test.js       # 自动起 内存MongoDB(PORT=4399) + AUTH_STUB=1，跑全 cmd 流程

# 明文调试
curl -X POST http://localhost:3000/gateway -H "Content-Type: application/x-www-form-urlencoded" \
  -d '{"cmd":2,"payload":{"loginType":0,"username":"test","password":"123456"}}'
```

- `.env`：`ENABLE_MEMORY_DB=true` 改用内存库（重启清空，仅联调）；`REQUEST_SECRET`/`JWT_SECRET`/`WECHAT_*`/`GOOGLE_CLIENT_ID` 等密钥只放服务端。
- 启动器 `scripts/dev.mjs` 会自动接管 27017 / 3000 上残留的本项目进程，Ctrl+C 一并关掉。

## 9. 禁止事项（红线，违反即回退）

1. ❌ handler 层写业务逻辑（必须薄转发）
2. ❌ service 层直接调 Mongoose Model（走 repository）
3. ❌ model 层写业务方法
4. ❌ 把 `coins` 等核心货币暴露给客户端写入
5. ❌ 新增 REST 路由，业务必须走 `/gateway`
6. ❌ 响应返回非 200 HTTP 状态码（业务错误走 `ErrorCode`）
7. ❌ 硬编码 cmd 数字（用 `CMD` 常量）
8. ❌ 配置表存动态数据（配置只读）
9. ❌ 扣费不用原子条件更新（`{ coins: { $gte: cost } }`）
10. ❌ 第三方登录信任前端声称身份（必须服务端验签/换 openid）
